一、根因

回滚至 14:05 基线后，「guage 自身前台」未被忽略：用户在软件内部切换到其他页面时，前台窗口是 guage 自己——

影响链后果
统计：前台会话被切换为 guage 自身（_activeProcess=guage），而概览图表中没有 guage 条目回到概览页后，被统计软件的应用时长不再更新（定格）
时长限制：_activeApp=guage，规则表中无 guage 规则 → 每秒判断不匹配即使已到设定时长也不触发提示/拦截

二、修复（最小精准，2 处）

文件改动
Core\Servicers\Instances\AppTimerServicer.cs前台切换事件中忽略 guage 自身：保持上一统计应用会话，概览页返回后时长继续按上一应用累计（_activeProcess 不切到 guage）
Core\Servicers\Instances\TimeLimitServicer.cs前台切换事件中忽略 guage 自身：_activeApp 保持上一应用，时长限制按用户使用的应用继续每秒判断，与页面切换无关

未改动统计累积算法、持久化逻辑、界面与其余功能（符合范围约束）。

四、验收自测清单（真机逐项）

  • 页面切换：使用任意软件 → 打开 guage 并切换到时长限制/设置等页面停留 → 返回概览页，该软件时长应继续按秒增长（≤1s 内更新）
  • 时长限制触发：为某应用设置短时限（如 1 分钟）并选「仅提示+消息弹窗」→ 使用该应用期间切换多个 guage 页面 → 到限时应弹出提示（与页面切换无关）
  • 后台恢复：最小化 guage → 使用其他软件 → 恢复 guage → 概览时长与实际一致（1s 内同步）
  • 多级导航：概览→详情→应用详情逐级返回概览，时长与限制判断一致
  • 持久化：重启 guage 后昨日/今日累计时长不丢失
  • 不阻塞：概览加载/刷新期间界面可交互、无白屏
