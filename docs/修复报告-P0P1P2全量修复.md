## 修复补记（2026-08-14 晚）：LoadGate 批次版本缺陷

**现象**：页面长时间处于加载状态、列表无数据。

**根因**：LoadGate 初版在每次 `Run` 时自增版本，同一刷新批次内的多个并发加载（概览页「主列表 + 更多列表」、统计页「4 个网页数据源」、详情页「LoadData + LoadInfo」）互相把版本顶掉，先完成的结果被判定为过期而丢弃，导致主要数据永不显示。

**修复**：LoadGate 改为「刷新批次」语义——每个用户触发的刷新调用一次 `BeginRefresh()` 获取版本号，批次内所有加载共享该版本；并新增 `onError` 回调用于异常时复位加载状态。IndexPageVM / ChartPageVM / DetailPageVM / WebSiteDetailPageVM 全部按批次版本改造（无参包装方法保留为单次刷新入口）。

**验证**：Debug/Release 构建通过；39 项测试全绿；应用启动后 UIA 检查无「暂时没有数据」空态与加载占位、无错误日志，页面正常显示数据。

## 修复补记（2026-08-15）：概览页无数据的最终根因（EF6 INNER JOIN 过滤未分类应用）

**现象**：即便 LoadGate 批次版本修复后，概览页依旧无数据、停留在白色加载占位；用户多次反馈「没有数据显示」。

**根因链**（诊断日志逐一确认）：
1. `AppData.Load()` 加载应用列表时用 EF6 查询（`.Include(m => m.Category)` 或 LEFT JOIN 匿名投影）。EF6 对与模型必需外键一致的 join 会**自动修正为 INNER JOIN**（忽略 `DefaultIfEmpty`）。
2. 用户数据库 `data.db` 中 138 个应用全部 `CategoryID = 0`（未分类），分类表无 ID=0 的行 → INNER JOIN 把**全部应用过滤掉**，`_apps` 加载结果为 0 行。
3. DailyLog 列表的 `AppModel` 因此全为 null → `IndexPageVM.MapToChartsData` 中 `item.AppModel.Name` 抛 NRE → apply 回调中断 → `IsLoading` 永不复位 → Charts 停在加载占位（白色光效）。

**修复**：
1. `Core/Servicers/Instances/AppData.cs` 的 `Load()` 改为**两段查询**：`db.App.ToList()` + `db.Categorys.ToList()`，内存中 `FirstOrDefault(c => c.ID == a.CategoryID)` 关联，未分类应用正常加载。
2. `IndexPageVM / ChartPageVM / DataPageVM / DetailPageVM` 四处 `MapToChartsData(DailyLogModel)` 全部改为**局部 `appModel` 判空**：null 时显示「未知应用」而非抛 NRE（含 ChartPageVM `LoadSelectedColData` 中 dynamic 遍历版本）。
3. 移除全部临时诊断代码（`Data.cs` 的 `[data]`、`Charts.cs` 的 3 处 `[charts]`），源码中不再有 `guage_diag.log` 写入。

**验证**：
- Debug/Release 构建通过（仅历史遗留 warning）；39 项测试全绿（退出码 0）。
- 应用启动后 UIA 枚举主窗口文本：概览页「今日最为频繁」列表渲染出 13 个真实应用（Windows Terminal Host / PixPin / Weixin / DeltaForceClient 等），无「暂时没有数据」、无加载占位。
- 临时冒烟轮巡（GUAGE_SMOKE 环境变量钩子，已移除）：IndexPage → ChartPage → DataPage → CategoryPage → TimeLimitPage → BreakReminderPage → SettingPage 七个页面依次导航，日志确认全部加载完成、**无任何页面崩溃/onError**。
- 遗留低噪日志（不影响功能）：浏览器统计图标 404 下载失败、`AddUrlBrowseTime` 非法时长 0、个别 favicon 解码失败。
