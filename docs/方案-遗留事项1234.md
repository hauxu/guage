## 遗留 1：异步加载「版本令牌」取消机制

**目标**：快速切换日期/标签/应用↔网站时，后启动的任务不再覆盖新数据；同时消除后台线程直接写绑定属性的写法。

**方案**：新增统一辅助类 `UI\Base\LoadGate.cs`（零依赖，约 40 行）：

```csharp
public class LoadGate
{
    private int _version;
    public int Next() => System.Threading.Interlocked.Increment(ref _version);
    public bool IsCurrent(int v) => Volatile.Read(ref _version) == v;

    // 后台加载，UI 线程校验版本后回填（版本不匹配即丢弃，杜绝陈旧数据覆盖）
    public void Run<T>(Func<T> loader, Action<T> apply)
    {
        int v = Next();
        Task.Run(() =>
        {
            try
            {
                T result = loader();
                Application.Current?.Dispatcher.BeginInvoke(() =>
                {
                    if (IsCurrent(v))
                    {
                        try { apply(result); }
                        catch (Exception ex) { Logger.Error(ex.ToString()); }
                    }
                });
            }
            catch (Exception ex) { Logger.Error(ex.ToString()); }
        });
    }
}
```

**改造范围**（每 VM 一个或多个 LoadGate，按数据域拆分）：

| 文件 | 涉及方法 | Gate 划分 |
|------|----------|-----------|
| `ChartPageVM` | LoadDayData / LoadWeekData / LoadMonthlyData / LoadYearData / LoadSelectedColData / LoadTopData / LoadDiffData / LoadWebData 系列 | 3 个：图表区 / 顶栏对比区 / 网页区 |
| `IndexPageVM` | LoadTodayData / LoadTodayMoreData / LoadThisWeekData / LoadThisWeekMoreData | 1 个 |
| `DetailPageVM` | LoadDayData / LoadWeekData / LoadMonthlyData / LoadYearData / LoadChartData 等 | 1 个 |
| `WebSiteDetailPageVM` | LoadData 及图表加载 | 1 个 |
| `DataPageVM` | LoadData | 1 个（现有 dataType 捕获保留，统一到 LoadGate） |

**验收**：快速连点「本周/上周/按天/应用↔网站」后界面最终状态与最后一次选择一致；构建通过。

**风险与工作量**：改动面约 4 个 VM / 20 个方法，但模式统一、改动机械，每改完一个 VM 构建一次。约 1 个会话轮次。

## 遗留 2：单元测试工程

**推荐方案 B（零依赖控制台测试台）**：

- 新建 `Tests\Guage.Tests`（.NET Framework 4.8 控制台工程，仅引用 Core），加入 `guage.sln`。
- 自带微型断言器 `Assert.cs`（AreEqual / IsTrue / Throws / Fail，约 20 行）。
- `Program.cs` 按模块跑用例，打印 PASS/FAIL 汇总，失败退出码非 0 —— 可直接命令行运行，日后接 CI 也简单。
- 配套小重构（提升可测试性，改动极小）：
  1. 把 `Data.UpdateAppDuration` 的时段/每日分桶抽为纯静态 `DurationBucketing.Split(DateTime start, int duration)`（本次 P0-1/P0-2 修复逻辑的核心，必须测）。
  2. `WebData` 的 MsgId 去重抽为纯静态 `MsgIdDeduper`。

**被测用例清单**：

| 模块 | 用例 |
|------|------|
| DurationBucketing | 跨小时、跨天、59:59 边界、每日 86400/时段 3600 封顶、起始小时含秒修正 |
| MsgIdDeduper | 重复 ID 拒绝、无 ID 放行、容量上限淘汰 |
| NetworkSecurity.IsPublicIpAddress | 全矩阵：0.0.0.0/8、10/8、100.64/10、127/8、169.254/16、172.16/12、192.168/16、198.18/15、224+/组播、::1、::、fc00::/7、fe80::/10、::ffff:192.168.x.x |
| UrlSecurity | http/https 放行、javascript:/file:/data: 拒绝、无协议补全 |
| TimeLimitServicer 纯逻辑 | 触发阈值、延长 5 分钟、当日标记去重（通过抽出的纯逻辑或反射） |
| BreakReminderServicer | 复用 docs 中反射测试台的 29 项断言（阶段流转/暂停/休眠兜底） |
| Unzip | 构造含 `..\..\evil` 条目的 zip → 验证拒绝；正常目录条目解压成功 |
| UpdatePackageVerifier | sha256sum/单行哈希/非法文本解析矩阵 |

- DB 相关用例用 `storage.path` 指针指向临时目录、跑完清理，避免污染真实数据。
- **方案 A（备选）**：若用户环境可联网，切换为 MSTest 工程 + vstest.console 运行，用例代码不变（仅换运行器）。

**验收**：`MSBuild Tests\Guage.Tests` 通过；运行后全部 PASS、退出码 0。工作量约 1 轮（含 2 处纯逻辑抽取）。

## 遗留 3：更新包签名（Ed25519 / minisign 风格）

**设计**：

- **签名对象**：对 `.sha256` 校验和文件签名（不签大 zip）：发布资产为
  `update.zip` + `update.zip.sha256` + `update.zip.sha256.sig`。
- **验签**：Updater 新增 `UpdateSignatureVerifier.cs`，引用 packages 中已有的 `Portable.BouncyCastle.1.8.9`（net40）实现 Ed25519 验签；公钥 Base64 内置源码，支持双公钥轮换（`PublicKeyV1/V2`，过渡期并存，发布侧换私钥后一个版本再移除旧公钥）。
- **签名工具**：新增 `tools\sign-release.ps1`：基于 BouncyCastle（Add-Type 加载 DLL）实现 Ed25519 密钥生成与签名；发布机执行一次
  `sign-release.ps1 -Zip update.zip -PrivateKey keys\guage-release.key`。
- **更新器流程改造**（`GithubRelease.cs` + `MainWindow.xaml.cs`）：
  1. 解析 release 资产中的 `*.sha256.sig`；
  2. 下载并验签（对 sha256 文件内容）；
  3. 验签通过后再做现有 SHA256 校验；
  4. 签名资产缺失或验签失败 → 中止更新（默认拒绝；设置页提供「允许未签名更新」开关，默认关）。
- **密钥管理**：私钥仅存发布机（不进仓库、不提交）；公钥进仓库；需用户提供公钥（或由脚本生成后把公钥给我嵌入）。

**验收**：篡改 zip/sha256（不重签）→ 更新器拒绝；正常包通过；脚本在发布机可独立跑通。

**前置条件（需用户参与一次）**：发布机生成密钥并保管私钥；提供公钥。

**工作量**：约 1 轮代码 + 用户一次密钥操作。

## 遗留 4：配置并发访问与性能项（4 个子项）

### 4a. `GetConfig()` 共享可变引用

- **现状**：UI 线程原地改配置对象，WebSocket 线程（WebFilter）与计时线程并发读。
- **方案（两步）**：
  1. **立即修热点**：`WebFilter` 不再每次直读配置 —— 在 `Init/ConfigChanged` 时把 `IgnoreURLList` 快照为本地副本（加锁），`IsDomainIgnore` 读副本，消除 WS 线程与 UI 线程的 List 结构竞态。（TimeLimitServicer/TimeLimitPageVM 已走副本路径，无需动。）
  2. **长期约定**：引入 `AppConfig.Update(Action<ConfigModel>)` 写时拷贝模式，新代码统一走它；存量原地修改调用点（右键菜单/设置页/详情页约 20 处）作为低优先级分批迁移。
- **验收**：WebFilter 竞态消除；其余读方均为「UI 线程写 + 后台读副本」。

### 4b. 数据页三路查询按需加载

- **现状**：`ShowType` 变化时无条件触发 3 次全量查询（2 次无用，且未初始化的日期为 `DateTime.MinValue` 会查公元 1 年）。
- **方案**：`DataPageVM_PropertyChanged` 的 `ShowType` 分支只加载当前标签一路（`_ = LoadData(当前日期, TabbarSelectedIndex)`）；MinValue 日期改为按 Tab 先初始化再加载。
- **验收**：切换应用/网站仅 1 次查询；日志中不再出现公元 1 年查询。

### 4c. 分类页 N+1 批量计数

- **现状**：每分类一次 `GetAppsByCategoryID().Count`、每网站分类一次 `GetWebSitesCount()`。
- **方案**：`IData`/`IWebData` 各加批量接口 `GetAppsCountByCategory()` / `GetWebSitesCountByCategory()`（单条 GROUP BY SQL），页面一次取回。
- **验收**：分类页刷新查询次数 O(N)→O(1)。

### 4d. 图标同步解码缓存

- **现状**：`ChartsItemTypeCard.Render` 每张卡片同步 `Imager.Load` 解码，20+ 张卡片时 UI 卡顿。
- **方案**：加轻量内存缓存（`ConcurrentDictionary<string, BitmapSource>` + `Freeze()`），首次解码后复用；不引入异步加载（改动最小、收益最大）。
- **验收**：同一数据源反复渲染不再重复解码。
