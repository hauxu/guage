## 五、有意不改（备案）

1. `TimeLimitServicer._banRestartSet` 在拿不到 `ExecutablePath` 时仍按进程名整杀：无路径信息时没有更可靠判据，宁可漏杀。
2. 上游遗留编译 warning（`CS0618 FormattedText`、`CS0414 _lastY`、`CS0067 CanExecuteChanged` 等）：不动，改它们只会引入未验证的 XAML 渲染偏差。
3. `Core/Librarys/SQLite/SQLiteBuilder.cs:171/202` 的「暂时不处理字段属性变化 / DROP TABLE」注释：沿用上游行为，改动需迁移框架级验证。
4. `RingTossWindow` 内的流场物理常数（`Γ_max`、`τ_in`、`τ_ν` 等）：观感已验收，不再调参。
5. 锁定遮罩不提供「隐藏」入口：遮罩的目的是强制，任何隐藏都是绕过口子（`RelockMinutes` 宽限期已覆盖正常解锁场景）。
6. 倒计时窗「三击隐藏」的残留限制（W1 备案，未修）：三击的第 2 下仍会先进入一次原地 `DragMove()`，若第 2、3 下之间指针移动超过系统双击容差，Windows 会重置 `ClickCount`，此时三击不被识别。指针基本不动（三击的自然手势）时正常工作。
   彻底消除需把拖动改成「按下捕获 + 位移阈值后 `DragMove`」，或把拖动移到专用拖动条——两者都改变交互模型，超出本次缺陷修复范围，故不纳入。
   触发条件若出现（用户反馈"三击偶尔没反应"），按上述两条之一改造。
